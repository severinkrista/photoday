# Шаг 2. Первый Android-прототип: Яндекс OAuth + чтение photoday.xlsx

## Что реализовано

В ветке `yadisk` добавлен Android-проект.

Первая функция:

1. запуск приложения;
2. подключение аккаунта Яндекса через официальный LoginSDK;
3. получение OAuth-токена;
4. сохранение токена в Android Keystore;
5. обращение к:
   `disk:/Файлы/Криста/Программы/photoday.xlsx`;
6. скачивание существующего XLSX;
7. чтение первой строки как шапки;
8. чтение колонок:
   - Дата
   - Время
   - День недели
   - Часть дня
   - Вид задачи
   - Задача
   - Сложность
9. вывод записей за последние N дней;
10. N по умолчанию равно 2 и может быть изменено в приложении.

Существующие строки файла не изменяются.

## 1. Что нужно сделать в Яндекс OAuth

Откройте:

https://oauth.yandex.ru/client/new/id/

Авторизуйтесь под тем Яндекс-аккаунтом, к которому относится ваш Диск.

Выберите создание приложения для авторизации пользователей.

Для платформы выберите **Android-приложение**.

### Android package name

Укажите:

`ru.krista.photoday`

Это значение уже зафиксировано в Android-проекте как `applicationId`.

### SHA256 Fingerprints

Для локальной разработки нужен отпечаток debug-сертификата.

На Windows в PowerShell выполните:

```powershell
keytool -list -v -alias androiddebugkey -keystore "$env:USERPROFILE\.android\debug.keystore" -storepass android -keypass android
```

Найдите строку:

`SHA256: ...`

Скопируйте этот отпечаток в настройки Android-приложения в Яндекс OAuth.

Если позднее APK будет подписываться другим сертификатом, его SHA256 нужно будет также зарегистрировать.

### Доступ к данным

Для текущего чтения нужен:

`cloud_api:disk.read`

Но поскольку следующим этапом приложение должно будет записывать новые задачи обратно в тот же XLSX, я рекомендую сразу добавить также:

`cloud_api:disk.write`

Итого:

- `cloud_api:disk.read`
- `cloud_api:disk.write`

Другие разрешения пока не нужны.

Яндекс рекомендует запрашивать только необходимые разрешения. Для нашей задачи чтение и запись Диска — именно те операции, которые планируется использовать. citeturn4search0turn3search14

### Client ID

После создания приложения скопируйте его **Client ID**.

**Client Secret в Android-проект передавать не нужно и мне его присылать не надо.**

Для мобильного приложения используется официальный Yandex ID LoginSDK. Яндекс документирует подключение LoginSDK для Android и получение OAuth-токена через него. citeturn3search7turn3search12

## 2. Настройка Android-проекта

В корне проекта создайте файл:

`local.properties`

Добавьте:

```
YANDEX_CLIENT_ID=ВАШ_CLIENT_ID
```

Например:

```
YANDEX_CLIENT_ID=1234567890abcdef
```

Файл `local.properties` уже добавлен в `.gitignore`, поэтому Client ID не попадёт в Git.

Не добавляйте в этот файл Client Secret.

## 3. Запуск

Откройте в Android Studio папку проекта из ветки `yadisk`.

Для актуального проекта используются современные версии Android Gradle Plugin / Kotlin / Compose. Проект ориентирован на Android API 26+.

Для сборки потребуется JDK 17.

После синхронизации запустите приложение на телефоне.

## 4. Первый запуск

Появится кнопка:

**Подключить Яндекс Диск**

Нажмите её.

LoginSDK передаст управление авторизацией Яндексу. Если на телефоне установлены приложения Яндекса, LoginSDK может использовать уже авторизованный аккаунт; иначе используется браузер/WebView. Это предусмотрено самим LoginSDK. citeturn3search0turn3search5

После разрешения доступа приложение получит OAuth-токен.

## 5. После авторизации

Приложение автоматически обращается к:

`disk:/Файлы/Криста/Программы/photoday.xlsx`

Через REST API Яндекс Диска.

REST API Диска предназначен в том числе для мобильных приложений и позволяет получать файлы пользователя и загружать их обратно. citeturn0search0

Публичная ссылка:

https://disk.yandex.ru/i/LGeuFBr2qWdOGg

в приложении не используется.

Используется именно авторизованный доступ к файлу по пути.

Сверху:

`Файлы / Криста / Программы / photoday.xlsx`

Затем:

`Последние дней: 2`

и кнопка обновления.

Ниже — записи из Excel.

Карточка записи показывает:

- дату;
- время;

- текст задачи;

## 7. Важное решение по существующему XLSX

Файл не преобразуется в новую структуру.

Используется именно существующая шапка:

| Колонка | Назначение |
|---|---|
| Дата | дата задачи |
| Время | время задачи |
| День недели | значение из файла |
| Часть дня | значение из файла |
| Вид задачи | тип задачи |
| Задача | описание выполненной работы |
| Сложность | оценка сложности |

Строки до 2114 и все существующие данные сохраняются.

## 8. XLSX-движок

Для первого прототипа подключён Android-совместимый порт Apache POI.

Это сделано специально через отдельный класс `XlsxReader`, чтобы при необходимости заменить движок, не переписывая интерфейс и работу с Яндекс Диском.

Важно: используемый Android-порт POI — сторонний проект, который был архивирован автором в 2022 году. Поэтому пока это **технический прототип**, а не окончательный выбор библиотеки. citeturn5search0

Сам Apache POI поддерживает чтение и изменение XLSX, но официальный POI не предоставляет современную Android-версию напрямую. citeturn5search6turn5search13

На следующем этапе обязательно проверим этот компонент на реальном `photoday.xlsx`.

## 9. Что будет следующим этапом

После проверки авторизации и чтения файла:

1. добавить сохранение новой задачи;
2. не менять существующую шапку;
3. добавлять новую строку в конец таблицы;
4. вычислять:
   - Дата
   - Время
   - День недели
   - Часть дня
5. записывать выбранные:
   - Вид задачи
   - Задачу
   - Сложность
6. загружать изменённый XLSX обратно на Яндекс Диск;
7. защититься от дублей при повторной отправке;
8. добавить настройки приложения;
9. сделать редактируемый список видов задач.
