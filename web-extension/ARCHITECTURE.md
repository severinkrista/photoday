# Архитектура «Фото дня»

Android-приложение и браузерное расширение работают с одним authoritative source: photoday.xlsx на Яндекс Диске.

## Слои

UI -> application/repository -> платформенный adapter -> Яндекс Disk REST API / XLSX.

TaskRecord — единая логическая модель записи: ID, дата, время, день недели, часть дня, вид задачи, задача, сложность, папка вложения, файл вложения.

Настройки имеют единый смысл: режим отображения, количество задач/дней, путь к XLSX, типы задач.

## Что не нужно дублировать

Не копируем Android UI в браузер и браузерный UI в Android.

Будущая аналитика должна получать TaskRecord из repository и быть независимой от конкретного экрана.

Правила предметной области вроде части дня, типов задач, формата имени вложения и расчёта следующего ID должны оставаться единым контрактом и проверяться тестами каждой платформы.

Момент записи — тоже единый контракт: дата и время выбираются в форме добавления (в том числе задним числом), а день недели и часть дня выводятся из них. В Android это `domain/TaskMoment.kt`, в расширении — `src/datetime.ts`.

## Что допустимо дублировать

Yandex API adapter и XLSX adapter являются платформенными реализациями. Android использует Kotlin и собственный XlsxCodec, браузер использует TypeScript и XLSX-библиотеку.

Это нормальная граница ответственности: искусственное объединение Kotlin и TypeScript исходников ухудшило бы поддержку.

## Authoritative source

XLSX на Яндекс Диске остаётся источником истины.

Локальные pending-записи — только очередь неотправленных изменений. После успешной записи в XLSX они удаляются.

## Напоминания

Настройки напоминаний (диапазон времени, частота, вкл/выкл) — часть `AppSettings`.
Service worker (`src/background.ts`) держит `chrome.alarms`-будильник с периодом из настроек и
показывает `chrome.notifications`-уведомление только внутри диапазона и не чаще заданной частоты
(время последнего уведомления хранится в `storage.local`).

Кнопка «ОК» в уведомлении открывает окно плагина для ввода новой записи: сначала через
`chrome.action.openPopup()` (Chrome 127+), при недоступности — отдельным окном
`popup.html?new=1`. Кнопка «Отмена» ничего не открывает. Открытие из напоминания помечается
флагом в `storage.session`, поэтому попап сразу разворачивается и ставит курсор в поле описания.

Момент уведомления не зависит от того, есть ли в таблице записи: это просто приглашение
описать завершённые задачи.

## OAuth

Браузер использует OAuth PKCE без client_secret. Токен хранится в browser extension storage и не передаётся на собственный сервер.

## Будущая аналитика

Рекомендуемый поток:

repository -> TaskRecord[] -> analytics services -> analytics UI

Например, отдельный TaskStatisticsService может считать количество задач, распределение сложности, типы, нагрузку по дням и динамику по периодам.

## Конкурентное редактирование

Android и browser сейчас работают по схеме read-modify-write. При одновременном редактировании файла Excel возможна гонка.

Перед массовым развитием стоит добавить optimistic concurrency: перед upload проверять состояние файла и не затирать изменения другого клиента.
