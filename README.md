# Фото дня

Проект содержит два клиента одной системы:

- Android-приложение в app;
- браузерное расширение в web-extension.

Оба клиента используют существующий photoday.xlsx на Яндекс Диске как authoritative source.

## Архитектура

UI -> repository -> платформенные adapters -> Яндекс Диск / XLSX.

Бизнес-контракт должен оставаться одинаковым, а UI и инфраструктурные реализации могут быть платформенными.

Браузерное расширение реализует:

- подключение к Яндекс Диску;
- чтение и запись photoday.xlsx;
- просмотр последних задач по количеству или дням;
- добавление задачи с указанием даты и времени (в том числе задним числом);
- типы задач;
- сложность 0–5;
- изображения-вложения;
- напоминания: диапазон времени и частота уведомлений;
- уведомление-напоминание: «ОК» открывает окно плагина в режиме новой записи (курсор в поле описания),
  «Отмена» просто закрывает уведомление, а нажатие на само уведомление тоже открывает форму —
  это запасной путь для браузеров, которые не передают расширению нажатия кнопок;
- на странице настроек в разделе напоминаний видно, что случилось с последним уведомлением:
  показано, нажали «ОК», нажали «Отмена» или закрыли; если нажатие до расширения не дошло,
  там же появляется подсказка;
- аналитика по таблице: выборки, группировки, графики (Chart.js) и тепловая карта активности;
- размер окна плагина меняется уголком в правом нижнем углу и запоминается для следующих открытий;
- виды задач выбираются кнопками в один ряд (остальные — из компактного списка «ещё N»);
- кнопка 📄 открывает саму таблицу: свою ссылку из настроек или файл в веб-интерфейсе Яндекс Диска;
- очередь неотправленных записей;
- повторную отправку и отмену;
- проверку подключения, XLSX и папки вложений;
- отдельную страницу настроек;
- автоматический учёт активных вкладок браузера: URL и заголовок страницы, время открытия и длительность сеанса;
- локальное хранение истории в JSON-структуре расширения и периодическую передачу сводок на Яндекс Диск;
- фильтрацию выгрузки: в ежедневный JSON попадают только сеансы длительностью больше 3 минут.

Автотрекинг настраивается в разделе «Настройки»: папка «Итоги дня» (по умолчанию `disk:/Итоги дня`), интервал отправки (по умолчанию 60 минут) и включение/выключение сбора. Внутри папки каждого дня создаётся `autotrack/autotrack.json`. Содержимое страниц и переписок не читается; параметры URL, похожие на секреты/коды авторизации, удаляются.

Браузерное расширение сейчас версии `1.0.0` (major: добавлен автотрекинг).

Подробная архитектура описана в web-extension/ARCHITECTURE.md.

## Сборка

Android:

- `build-apk.bat` — сам скачивает Gradle 9.6.0 и JDK 17 в `.tools`, собирает debug-APK
  и кладёт его в `build-output/photoday-<версия>.apk`;
- версии Gradle, Android Gradle Plugin и Kotlin Compose задаются в одном месте —
  `settings.gradle.kts` (`pluginManagement { plugins { ... } }`). Не дублируйте `version`
  в `build.gradle.kts` и `app/build.gradle.kts`: разные версии в двух файлах дают ошибку
  «the plugin is already on the classpath with a different version».

Браузерное расширение:

- `cd web-extension && npm install && npm run build` (TypeScript + esbuild);
- собранные `popup.js`, `settings.js`, `viewer.js`, `background.js`, `analytics.js` в корне
  `web-extension` коммитятся, их пересобирает workflow `.github/workflows/web-extension-build.yml`.
